# 測度 — 台股基本面研究工具（前端）

彙整台股公開財報、月營收與法人進出，計算基本面指標，並依使用者自訂條件篩選個股。

> **資料為臺灣證券交易所公開資料的每日快照。**
> 由 `scripts/fetch-twse.ts` 抓取後寫進 `data/*.json`，前端只讀這些檔案，
> 建置與執行期都不對外連線。**本專案呈現公開資料與依設定計算出的指標，不構成投資建議。**

## 現況

前端 + 真實資料快照層。資料收集器（`scripts/`）扮演 PRD 裡 Data Collector 的角色，
差別只在落地成 JSON 而非 PostgreSQL；PostgreSQL、FastAPI、AI Analyzer 尚未實作。
讀取層 `src/lib/data/` 與收集器之間以固定介面隔開，日後改接資料庫時 UI 不需改動。

| 頁面 | 路徑 | 說明 |
| --- | --- | --- |
| 落地頁 | `/` | 專案說明與範圍邊界 |
| 市場概況 | `/dashboard` | 大盤指數、成交量、三大法人、漲跌家數 |
| 個股 | `/stock/[id]` | K 線、財務指標、月營收、股利、財報摘要 |
| 選股篩選 | `/screener` | 自訂條件篩選（支援相對條件），條件存在網址 |
| 追蹤清單 | `/watchlist` | 追蹤標的的價格與基本面變化，存在 localStorage |

收錄 12 檔標的：2330、2454、2382、3711、2317、2891、1301、2308、2412、3034、1216、0050。

篩選條件除了絕對數值，也支援「高於去年」與「低於同業平均」——
門檻會隨每檔個股自身的歷史與所屬產業浮動。同業平均取全市場（約千檔）同產業的
本益比中位數，不是只拿收錄的 12 檔來平均，否則半導體只有 3、4 檔、算出來沒有意義。

## 資料收集

```bash
npm run fetch:twse       # 完整：含 MOPS 逐季財報與股利（約 30 分鐘）
npm run fetch:daily      # 每日：只更新行情／大盤／法人／月營收（約 5 分鐘）
npm run typecheck:scripts
```

兩種模式對應不同更新頻率。逐季財報一季才換一次、股利一年幾次，天天全抓既慢又
徒增 MOPS 被擋的風險；`--daily` 略過那兩步，`fcf` 由既有 `quarterly.json` 重算 TTM、
`epsCagr5y` 沿用既有 `metrics.json`，且不覆寫 `quarterly.json`／`dividends.json`。

自動更新走 GitHub Actions（`.github/workflows/`）：`refresh-daily` 於交易日收盤後跑
`fetch:daily`、`refresh-full` 每週跑完整版，兩者都只在資料真正有變動時才 commit
（`meta.json` 的時間戳單獨變動不觸發），push 後由部署平台自動重建。
MOPS 反爬蟲從機房 IP 可能較兇，被擋的個股會降級為無逐季並列入缺漏報告；
若常態被擋，改用 self-hosted runner。

來源全部是 TWSE / MOPS 的公開端點，不需要金鑰：

| 資料 | 端點 | 粒度 |
| --- | --- | --- |
| 日成交（全市場快照） | `openapi …/STOCK_DAY_ALL` | 一次全市場 |
| 本益比 / 淨值比 / 殖利率 | `openapi …/BWIBBU_ALL` | 一次全市場 |
| 月營收（含 YoY） | `mopsov …/t21sc03_*.csv` | 一次全市場 / 月 |
| 最新一季損益 / 資產負債 | `openapi …/t187ap06,07_L_ci`（金融股 `_fh`） | 最新一季 |
| 逐季損益 / 資產負債 / 現金流 | `mopsov …/ajax_t164sb04,03,05`（金控 `step=2` 合併報表） | 逐股 × 逐季 |
| 歷年股利分派 | `mopsov …/ajax_t05st09_2` | 逐股 × 逐年 |
| 公司基本資料 | `openapi …/t187ap03_L` | 一次全市場 |
| 大盤指數 | `openapi …/MI_INDEX` | 當日快照 |
| K 線歷史 | `www …/STOCK_DAY` | 逐股 × 逐月 |
| 大盤加權指數與成交 | `www …/FMTQIK` | 逐月 |
| 三大法人（逐檔） | `www …/T86` | 逐日 |
| 三大法人買賣超金額 | `www …/BFI82U` | 逐日 |

收集器最要緊的一段是**基準日對齊**：盤後 `www.twse.com.tw` 的逐日檔會先有當天資料，
`openapi` 的全市場快照要晚一個交易日才跟上。本益比、漲跌家數只有快照有，補不到更新的那天，
所以以快照日為唯一基準，把所有序列砍到那天為止；寫檔前並 assert
「表頭現價 == K 線最後一根收盤」，對不上就讓收集失敗，不產出錯的快照。

逐季財報同樣有個靜默陷阱：MOPS 損益表與現金流量表給的是「年初至今累計」數，
畫單季要逐季相減；而 Q2／Q3 頁面比 Q1／Q4 多一個「第N季（三個月）」欄擠在累計欄前面，
用固定欄位位置解析會抓到單季當累計、相減後整條趨勢全錯卻看起來合理。因此一律靠表頭
「MM月01日至…」認出本年累計欄，見 `scripts/twse/financials-history.ts`。

## 真實資料的形狀（哪些欄位可能沒有值）

真實市場不像 mock 那樣每格都有漂亮的數字。缺值一律以 `null` 表示、畫面顯示破折號，
**絕不用 0 代替** —— 本益比 0 和「沒有本益比」在篩選與評分上是完全不同的意思：

- **虧損公司沒有本益比**（如 1301 台塑）：EPS、PE 為 `null`，PE 條件一律不通過。
- **金控 / 銀行沒有「營業收入」**（如 2891 中信金）：毛利率、營益率、淨利率不成立，
  損益結構是利息淨收益型，因此不畫利潤率趨勢、也無自由現金流；但有逐季 EPS 趨勢
  （走 `step=2` 的金控合併報表）、月營收、ROE 與歷年股利。
- **ETF 沒有公司財報**（0050）：估值、財報、月營收、評分整段不適用。

以下欄位在**金控與 ETF** 上仍為 `null`（來源就沒有），一般業則有真實值：

- `fcf`（自由現金流）：一般業由 MOPS 現金流量表算近四季 Σ(營業現金流 − 資本支出)；
  金控／ETF 無現金流量表，為 `null`。
- `epsCagr5y`（EPS 五年 CAGR）：由 MOPS 逐年全年 EPS 回歸（金控走合併報表）；
  缺五年兩端點或虧損（起點非正）者為 `null`。

評分引擎在**有值的分項上重新配權**，而不是把缺項當 0 系統性低估每一檔。

季度利潤率 / EPS / 現金流趨勢圖，是 MOPS 財務報表近 12 季逐季相減後的**真實單季值**
（見 `scripts/twse/financials-history.ts`）。金控只有 EPS 趨勢（無營收→無利潤率、無現金流），
ETF 沒有逐季資料、趨勢圖為空狀態。

歷年股利為 MOPS 股利分派情形的**真實逐年值**（現金＋股票股利，按季配者加總全年，
見 `scripts/twse/dividends.ts`）。配息率以當年全年 EPS 計；殖利率以現價為分母，
屬近似——歷年逐日股價無法回溯，這點在畫面上不宣稱是歷史殖利率。

## 兩處使用者狀態

**篩選條件放在網址，不放在 component state。** 調出一組有意義的條件之後，
使用者會想存書籤或貼給別人；放在 state 裡重新整理就沒了，也沒有東西可以分享。
格式是看得懂的字串，網址本身就是說明：

```
/screener?q=roe:gt:15,revenueYoy:gt:10,debtRatio:lt:50,pe:lt:ia
```

`ly` = 去年同期、`ia` = 同業平均。網址是不可信輸入 —— 壞掉的單一條件會被跳過
而不是整組退回預設，因為分享出去的連結少一個條件比整個篩選器重置好懂。
編解碼與防禦見 `src/lib/rule-url.ts`。

**追蹤清單放在 localStorage**，結構比照既有的漲跌配色偏好（`useDeltaColors`）——
兩者都是「localStorage 裡的使用者偏好」，沒有理由用兩套寫法。
同樣以 `useSyncExternalStore` 訂閱，因此多個分頁會保持一致。

清單只決定「顯示哪幾列」，每一列的欄位值仍由 server component 先算好再傳進來，
不需要把整個資料層打包進 client bundle。

## 開發

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # 靜態預渲染 19 頁
npm test        # vitest
```

測試集中在會靜默出錯的地方：`deltaClass()` 的紅漲綠跌、
screener 的相對條件（去年 / 同業平均）與缺值處理，以及快照本身的一致性
（`src/lib/data/prices.test.ts`：每一檔的表頭現價 == K 線最後一根收盤、
日期 == 基準交易日）—— 這些算錯時畫面看起來完全正常，
每個數字單看都合理，只有湊在一起才是錯的。screener 的測試刻意不寫死任何數值，
全部由當下的真實指標動態導出，資料每次更新後斷言仍然成立。

另外兩處是不可信輸入的解析：網址裡的篩選條件與 localStorage 裡的追蹤清單。
兩者都可能是舊格式、別的分頁寫壞的、或使用者自己改過的，
壞資料會一路走到 `COMPANY_BY_ID.get(id)!` 那個沒有 fallback 的驚嘆號。

## 兩個實作上的重點

**台股漲跌顏色與歐美相反 —— 紅漲綠跌，且可由使用者自訂。**
所有漲跌配色必須經過 `deltaClass()`（`src/lib/format.ts`），
不要在元件裡直接寫 `text-red-500`。圖表用 `CHART_COLORS`。

自訂配色只換 `--color-up` / `--color-down` 兩個 CSS 變數的值，
語意 token 名稱不動 —— 因此全站 80 幾個 `text-up` / `bg-down`
使用點都不需要修改。偏好存在 localStorage，並由 `layout.tsx` 中的
阻塞腳本在繪製前套用（若等 hydration 才套，會有一瞬間顯示相反的漲跌資訊）。

例外是 canvas 繪製的 K 線圖：`var()` 在 canvas 中無效，
必須用 `useChartColors()` 取實際色碼，見 `src/components/charts/useChartColors.ts`。

**Tailwind v4 的 CSS 變數語法。**
色彩 token 定義在 `globals.css` 的 `@theme`，會自動產生 `text-up`、`bg-surface`
等 utility。**不要**用 v3 的 `text-[--color-up]` 寫法 —— v4 會輸出
`color: --color-up`（缺少 `var()`），瀏覽器直接丟棄，顏色會靜默失效。

## 視覺驗證

介面在真實資料（2026-07 快照）下逐頁目視確認過，包含兩個邊界：
金控股 `/stock/2891`（無毛利率、有月營收）與 ETF `/stock/0050`（財報整段不適用）。
預設與自訂配色（橘漲藍跌）各跑一輪，K 線（canvas）與 Recharts 都跟著換色，
缺值欄位一律顯示破折號而非 0，console 無錯誤。

接真實資料時抓到並修掉的問題：

- **基準日錯位造成表頭與 K 線不一致。** 抓取當下 `openapi` 快照停在前一交易日、
  `www` 的 K 線已有當天資料，混在一起會讓表頭現價與 K 線最後一根差一天。
  已在收集器統一砍到快照日，並在寫檔前 assert 兩者相等。
- **月營收單位差 1000 倍。** MOPS 的營收 CSV 以「千元」計，UI 以「元」顯示，
  台積電 6 月營收一度顯示 4.4 億（應為 4,426 億）。已在收集器乘回。
- **金控股被誤判為 ETF。** 金控沒有毛利率、季報趨勢為空，原本與月營收共用一個閘，
  一空就整段當成「ETF 無財報」。已拆成各自獨立的顯示條件。
- **缺值顯示成「—x」。** 虧損股沒有本益比時 `formatPrice(null)+"x"` 會印出「—x」。
  改用 `formatMultiple()`，缺值時只顯示破折號。

高密度表格在窄螢幕採容器內橫向捲動（`overflow-x-auto` + `min-w`），
頁面本身不會橫向溢出 —— 維持數字對齊優先於塞進畫面。

已在真實瀏覽器與實機上目視確認過。仍未涵蓋的是自動化：
還沒有視覺回歸測試，版面若被改壞不會有測試擋下來。
